# What a consumer's cockpit can know — the records behind the Cell evidence tab

Research for the ticket "What a consumer's cockpit can know", a child of the map "Cockpit tabs that explain why each Cell is used".

**Read at `origin/main` = `2943966e`** (fetched 2026-10-26). Every `path:line` below is that sha, read from a worktree cut from it; the main checkout's `main` is behind and was not read. Two kinds of fact are marked apart:

- **`[local]`** — observed on this machine on 2026-10-26: this workspace's gitignored `.fleet/` and scratch root, omp's own config and a `ticket-router.mjs fit` / `pr-cost.mjs --json` run read-only against a `/tmp` table. These are examples of what a record holds, not claims about the sha.
- **`[INFERENCE]`** — read off code, not exercised.

omp behaviour is cited from omp 18.12.6's own docs (`omp://…`), only where a fact depends on it.

Vocabulary is CONTEXT.md's: Cell, Cell generation, Declared tier, Resolved tier, Tier route, Router, Stratum, Objective, Spend, Work time, Ruling, Exploration Pull, Admissible row.

## Answer in brief

1. **A consumer's `ticket-router.mjs route` reads two files and no others of its own evidence:** the router table installed *beside the script* (`DEFAULT_TABLE = join(SCRIPT_DIR, "router-table.json")`, `plugin/scripts/ticket-router.mjs:61-62`; the Pull passes no `--table`, `plugin/scripts/pull.mjs:942-946`) and the workspace's own `.fleet/cost-guard.json` (`plugin/scripts/pull.mjs:1260`). The table is this repository's evidence, fitted only by a repo-local duty the plugin never ships. So a consumer's **rows, `reasons`, `estimates`, `burn_in`, `stage` and `cells` are this repository's**; only the guard (`tripped`, per-Cell `n`) is the consumer's own.
2. **The table can describe models the consumer does not run.** Its `estimates` name a Cell generation by model (`generation`, `older`) of the *maintainer's* `modelRoles`; `reasons` name only Cell tokens. Nothing in the table or the router ties either to the consumer's `modelRoles`. Today the shipped table is unfitted (`estimates: {}`), so the hazard is latent.
3. **A fresh consumer has no guard file at all** until its first close-out (`metrics-refresh.mjs` skips the guard while a metrics TSV is missing), so its first run routes the default Cell only, `REASON=guard-missing`. After that first close-out the guard exists with `verdict: "none"`; the shipped table is in burn-in, so every Pull is an Exploration Pull drawn uniformly over the three stage-1 Cells.

## 1. `plugin/scripts/router-table.json`

**Shape and current content.** The committed file is the unfitted seed: `fitted_commit: null`, `window_start: null`, `n_rows: 0`, `stage: 1`, `cells: [slow-high, task-high, smol-high]`, `burn_in: true`, `rows.{cost,speed}["*"] = "slow-high"`, `classifier: {b: null, tau: null}`, `estimates: {}`, `reasons.{cost,speed}["*"] = {cell: "slow-high", reason: "unjudged", cells: {}, pairs: []}`, `guard: {tripped: [], n: {}}` (`plugin/scripts/router-table.json:1-47`). Its schema is `validateTable` (`ticket-router.mjs:115-152`); the design spec's R3 gives the full fitted shape (`docs/specs/2026-09-28-model-effort-router-design.md:531-563`).

**Writer.** Only `ticket-router.mjs fit`, which rewrites `--table` through a `.tmp` rename (`ticket-router.mjs:756-758`) and records the commit sha as `fitted_commit` (`:21-31`). `fit` reads the three TSVs *as committed at `--commit`* with `git show`, never the working tree (`:23-24`, `:695-700`), and the guard file at `--guard` (`:746-748`). `fitTable` is an exported pure function (`:491`).

**Trigger — repo-local only.** The plugin never runs `fit`: the only callers of `ticket-router.mjs` under `plugin/` are `route` (`pull.mjs:946`, `pull.md:249`) — a grep of `plugin/` finds no `fit` or `--check` call. The re-fit is `routerFit()` in `.omp/skills/run-team-local/hook.mjs:209-257`: once `fit --due` prints `DUE=yes` (≥ `FIT_EVERY_MERGED` = 50 merged PRs whose features rows the fitted commit lacks, `ticket-router.mjs:74`, `:749-754`) and no `chore/router-fit-*` PR is open (`hook.mjs:220-222`), it fits in a throwaway checkout of `origin/main` (`:211-217`) and opens a `patch`-labelled chore PR (`:242-243`). `run-team-local/SKILL.md:56-69` says the PR is never merged by the run and is stopped for a human because `router-table.json` is not an Inert diff. The skill is triggered by this repository's `AGENTS.md:39-40`, and "the plugin never calls it" (`SKILL.md:9-14`). `.omp/` is not in `plugin/package.json`'s `files` (`agents, commands, skills, scripts, .claude-plugin, LICENSE, NOTICE`), so it does not ship.

**Guard on hand edits.** CI re-fits from `fitted_commit` and fails on any difference: the table is "a code carrier" (`ticket-router.mjs:32-37`, `.github/workflows/ci.yml:175-189`). A hand-edited table cannot merge.

**Whose runs.** The corpus at `fitted_commit` — this repository's `docs/metrics/` (`hook.mjs:215-217`). `[local]` A preview fit of today's `origin/main` corpus into `/tmp` read 195 Pulls and named Cell generations `claude-opus-5-5` (slow-high), `claude-sonnet-5-5` (task-high), `claude-haiku-5-5` with `claude-haiku-4-5` older (smol-high) — the models of the maintainer's `modelRoles` (§ 6).

**When it changes, and what a consumer sees.** Only on a merged re-fit (never so far: `fitted_commit` is null). It reaches a consumer only inside a new plugin package, because the Resolver finds scripts under the installed package: `fleet-run` resolves `~/.omp/plugins/node_modules/@feigi/fleet-ctl` to its realpath and runs `<install>/scripts/<script>` (`plugin/scripts/fleet-run:7-13`, `:72-74`); `pull.mjs` runs its sibling scripts from its own directory (`pull.mjs:143`, `:636-639`). The spec states the intent: the table "lives under `plugin/` because the route script runs from the installed plugin" (`docs/specs/2026-09-28-model-effort-router-design.md:549`). With `omp plugin link` the install root is the linked checkout (`fleet-run:7-13`).

**Read cost.** ~700 B unfitted; ~9.2 KB fitted `[local]`. A `stat` per tick is enough to know it changed.

**`burn_in` is a static boolean in the file.** `route` reads `table.burn_in` (`ticket-router.mjs:262`); only a fit recomputes it as "not every Cell in `cells` has guard `n ≥ MIN_N`" (`:531`, `:517`). A consumer's own per-Cell `n` never turns it off.

**Verdicts the tab can show** (`ticket-router.mjs:388-412`): per candidate `tripped`, `too-few`, `under-floor`, `too-dear`/`too-slow`, `not-reliably-cheaper`/`-faster`, `qualifies`; per row `reason` ∈ `unjudged`, `no-qualifier`, `sole-qualifier`, `reliably-cheaper`/`-faster`, `lower-fail-rate`, `lower-usd`/`fewer-minutes`, `name`. `estimates[stratum][cell]` carries `generation, n, merged, claims, failed, usd_per_merged, minutes_per_merged, fail_rate, fix_rounds, review_findings, left_out, unpriced, untimed, excluded, older` (`:329-349`); `review_findings` is always `null` and `fix_rounds` is "report-only" (`:338`, `docs/specs/2026-09-28-model-effort-router-design.md:555-556`) — the tab does not need either. `classifier` is `null` (arm B is not live, `bArmLive`, `:159-161`).

**Which row set routes.** `rows[objective]`, the Objective being the run's: `phase0.mjs --objective`, default `cost` (`phase0-receipt.mjs:147-148`), fixed per run in `.fleet/phase0.json` (`phase0.mjs:586-654`); `route` reads it from the receipt when omitted (`ticket-router.mjs:663-669`). A stratum with no row follows `*` (`:163`).

**Stage-2 Cells.** Definitions for `slow-medium` and `task-max` already ship (`plugin/agents/fleet-implementer-slow-medium.agent.md:4`, `…-task-max.agent.md:4`), but they enter `cells` only at a stage-2 fit (`STAGE2`, `ticket-router.mjs:76`, `:519-524`). `tier-roles.mjs` treats a Cell outside the table's `cells`/`rows` as non-routable (`tier-roles.mjs:141-156`). `[local]` the preview fit put both at n=0 and set `burn_in: true`, `stage: 2`.

## 2. `.fleet/cost-guard.json`

**Writer & trigger.** `pr-cost.mjs --guard` writes it (`pr-cost.mjs:337-346`; `guardFile` `:248-261`). Its only caller is `metrics-refresh.mjs` (grep of `plugin/`), which passes `--out <workspace>/.fleet/cost-guard.json` (`metrics-refresh.mjs:117-120`). `metrics-refresh.mjs` runs at **phase 0**, after the fast-forward and before the first Pull is routed (`phase0.mjs:51`, `:267-271`; `phase-0.md:151-168`), and at **close-out**, after the scrape and every ruling append and before the commit (`closeout.mjs:25-40`, `:277-280`; `close-out.md:100-118`). A failed refresh leaves the old file on disk, which is why the verdict carries `computed_at` (`fleet-tick.mjs:495-502`). Without `--out` the path is `fleetFile("cost-guard.json")` — the **main** workspace's `.fleet/`, whichever worktree runs it (`pr-cost.mjs:267-279`, `fleet-dir.mjs:1-22`).

**When it changes.** Twice per run, nothing in between. It is computed from the *working-tree* TSVs at that moment, so each input has its own cadence: rulings are appended mid-run (`SKILL.md:279-283`), the member scrape lands only at close-out (`closeout.mjs:30-33`), the features drain at phase 0 and close-out. `[INFERENCE]` After close-out the TSVs are committed on a branch and the checkout returns to `main` (`closeout.mjs:41-49`), so on disk `docs/metrics/*.tsv` can be older than the guard computed a step earlier, until the artifacts PR merges and the next phase 0 fast-forwards. `[local]` At 2026-10-26T19:17Z the live guard read `smol-high n=32`, while the same `origin/main` corpus fits to `n=31` — the two judgements read different corpora.

**Whose runs.** The workspace's: members/tier/features TSVs from the cwd-relative `docs/metrics/` (`pr-cost.mjs:299-306`; `metrics-refresh.mjs:51-54`, `:114-127`) and one `gh pr list --state all --search created:>=2026-10-03` for merged state (`pr-cost.mjs:314-320`). The window is the constant `WINDOW_START = "2026-10-03"` (`:75-77`), "reset only by editing this constant in a reviewed change" — a consumer is held to the same date. `[local]` the full report took ~4–5 s wall, almost all of it the `gh` call.

**What it holds.** Verdict, baseline and trips are each Cell's *newest generation* alone (`pr-cost.mjs:55-58`, `:132-145`). A Cell trips when `merged ≥ MIN_N` (20) and either its fail rate is ≥ 15 points above `slow-high`'s (`TRIP_POINTS`, `pull-attribution.mjs:99-105`, integer counts) or its mean $ per merged PR is ≥ the baseline's (`pr-cost.mjs:95-100`, `:139-145`). `n` in the file is merged PRs (`:253`). `retire` is true when every non-default stage-1 Cell tripped while no row of the shipped table adopts one — the guard of a consumer reads *this repository's* installed table for that (`:146-149`, `:309-310`).

**Persisted fields** (`pr-cost.mjs:248-261`): `computed_at`, `window_start`, `baseline{cell,generation,n,mean_usd,fail_rate}`, `cells[]{cell,generation,n,mean_usd,fail_rate,untimed}`, `tripped[]`, `verdict` (`ok`|`tripped`|`none`), `retire`, `min_n`. `[local]` Today's file: all three Cells present, `tripped: []`, `verdict: ok`, baseline `slow-high` `claude-opus-5-5` n=69, $14.92, fail 0.1159.

**Not persisted** — computed by `computeReport` (`:102-162`) and lost: `n_claims`, `n_failed`, `median_usd`, `router_usd`, `usd_diff_ci95`, `excluded`, `left_out`, `unpriced`, each Cell's older generations, `pending` PRs, the A/B report and the pricing cross-check. Consequences for the tab: the "$ against `slow-high`" leg is exact from the file; the "fail-rate gap against the 15-point floor" is exact only from integer counts, which the file lacks (it has `fail_rate` rounded to 4 places); the "Pulls left out, unpriced or untimed" trust signal exists in the file only as `untimed`. The fuller figures exist in two places: a recompute (`computeReport` is exported, `:102`; `pr-cost.mjs --json` without `--guard` writes nothing) or, after a fit, the table's `estimates`.

**Readers and their strictness differ.** The router's `readGuard` accepts a guard with a `tripped` array of Cell tokens and `cells[]` with `cell` and numeric `n`, else `null` (`ticket-router.mjs:175-185`). `fleet-tick.mjs`'s `readCostGuard` additionally requires `verdict ∈ {ok,tripped,none}`, `computed_at`, a well-shaped baseline and `verdict === "tripped"` iff `tripped` is non-empty (`fleet-tick.mjs:526-546`). A guard that satisfies the former can fail the latter; the cockpit has to pick one.

**Fresh consumer.** No guard until the first close-out: `metrics-refresh.mjs` skips the duty while any of the three TSVs is missing — "no corpus to guard yet (its first run)", leaving `.fleet/cost-guard.json` as it is (`metrics-refresh.mjs:27-33`, `:114-116`; `phase-0.md:164-168`). The router then degrades: `guard === null` → `REASON=guard-missing`, `POLICY` and `CELL` both the default Cell, no draw (`ticket-router.mjs:248-252`; `pull.md:270-272`), "the guard cannot be evaded by deleting it". `fleet-tick` prints `DEFAULT-ONLY — cost-guard.json missing` (`fleet-tick.mjs:508`).

## 4. `.fleet/ticket-features.pending.tsv`

**Writer.** `ticket-router.mjs route` appends one row per Pull, with the header on first write (`:674-685`). The path is `ticket-features.pending.tsv` beside `--guard` (`:674`); `pull.mjs` passes `<fleetDir>/cost-guard.json` (`pull.mjs:1260`, `:942-945`), so it is the main workspace's `.fleet/`. One controller per checkout is the rule; the append takes no lock (`:675-678`).

**Row.** `run_date` (the UTC date in the session id, `:201-204`), `session`, `agent: impl-<N>`, `ticket`, `policy_cell`, `chosen_cell`, `exploration_draw` (`k/K`, blank when no draw), `sizing_src`, `sizing_pre`, `router_usd`, the issue metrics (`brief_chars`, `criteria`, `comments`, `age_days`, `paths`, `test_paths`, `xrefs`, `kind`) and `objective` (`:275-279`).

**When it changes / lives.** From a Pull's route step until the next drain (phase 0 or close-out). A `route` that exits 2 — a usage error or an unreadable or invalid table — appends nothing: it dies at `ticket-router.mjs:641-646`, before the append at `:674-685`; `pull.mjs` then releases the claim and the Pull is over (`pull.mjs:948-957`). `[INFERENCE]` Because the file is empty between a drain and the next route, it is the only record that lists *this run's* Pulls with their Cells before the drain; after the close-out drain the same rows live in `ticket-features.tsv`.

**For the tab.** The pending file plus the ledger's `route=` token gives a live Pull's `policy_cell` ≠ `chosen_cell`, its draw `k/K`, its Objective, and its Stratum inputs. It cannot say `REASON=ok`, since `ok` is never written to the ledger.

**Fresh consumer.** Created by the first `route` — which in a fresh consumer routes with `REASON=guard-missing` (`policy_cell = chosen_cell = slow-high`, `exploration_draw` blank).

## 5. The ledger's `tier=` and `route=` tokens

- **Written by** `pull.mjs`'s `row` step (`pull.mjs:964-972`): `<member>[ · tier=<CELL>][ · route=<REASON>]`. `tier=<CELL>` exactly when `DRAW` is not `-`; `route=<REASON>` for any `REASON` other than `ok` (`pull.mjs:967`; `pull.md:249-254`, `:269-272`). `ledger.mjs row` validates a `tier=` value as a Cell token (`ledger.mjs:751-755`; `ledger-grammar.mjs:823-832`) but not `route=`, which is free text ("a freeform … token", `docs/specs/2026-10-13-one-command-per-wake.md:93`); `route=` is not read by any script (grep of `plugin/scripts`: only the writer at `pull.mjs:967`).
- **A replacement** inherits the row's tier; `ledger.mjs token <N> tier=<cell>` changes it only once the implementer has settled (`pull.md:437-444`; `ledger.mjs:2928-2975`).
- **Lifetime.** One ledger per run: phase 0 moves the previous ledger aside (`ledger.mjs:1520-1526`, archive `ledger.<stamp>.md`, `:1651-1665`). The archive is local state, gitignored (`.fleet/`); `[local]` this workspace's archives reach back to 2026-08-13 and carry `route=guard-missing` rows in the 2026-10-08…2026-10-11 archives and none after.
- **Reachable by the cockpit already.** `board-gather.mjs` runs `ledger.mjs read` each tick (`board-gather.mjs:750`), whose JSON is the raw `rows` (`ledger.mjs:733-734`), so the tokens are in the payload the board already holds; `compute-board.mjs` does not parse them (grep: no `tier=`/`route=` reader in `board*.mjs`/`compute-*.mjs`).
- **Fresh consumer.** Same grammar. Run 1: `route=guard-missing` on every row, no `tier=`.

### The Pull state record (not on the ticket's list, and the richest)

`pull.mjs` saves `st.route = { line, cell, draw, reason, implRow, chainHead }` (`pull.mjs:959`) in `<scratch>/impl-<N>/pull.json` (`STATE`, `:151`; scratch root `~/.fleet/scratch/<basename>-<8 hex>`, `fleet-dir.mjs:143-157`; `setup()` `pull.mjs:1239-1265`). `line` is the router's whole print: `POLICY=… CELL=… DRAW=… STRATUM=… OBJECTIVE=… REASON=…` — the only record of `STRATUM` and of `REASON=ok`. `[local]` `impl-3748/pull.json`: `route.line = "POLICY=slow-high CELL=task-high DRAW=3/3 STRATUM=heavy OBJECTIVE=cost REASON=ok"`. It is not version-controlled, is overwritten when the ticket is Pulled again (the previous state goes to `pull.previous.json`, `:152`), and exists on the machine of the controller; a Pull that never reached routing has `route: null` (`[local]` `impl-3845`). The cockpit and the controller run on the same machine (`board.mjs serve` is launched by phase 0, `phase0.mjs:52-53`), so a hand-launched cockpit can read it.

## 6. Declared tiers and `modelRoles`

**Declared tier.** `plugin/agents/<name>.agent.md` line 4 `model: "@<role>:<level>"` (CONTEXT.md:567-572). The five implementer definitions: `slow-high`→`@slow:high`, `slow-medium`→`@slow:medium`, `task-high`→`@task:high`, `task-max`→`@task:max`, `smol-high`→`@smol:high` (`plugin/agents/fleet-implementer-*.agent.md:4`). Every other definition (`fleet-finisher` `@smol:low`, `fleet-fix-applier` `@slow:high`, `fleet-merge-bot` `@smol:low`, `fleet-recipe-deriver` `@task:medium`, `fleet-review-correctness`/`-simplify` `@slow:high`, `-silent-failure` `@task:high`, `-comments`/`-tests`/`-types` `@task:medium`, `-verifier` `@task:low`, `-runner`/`-snapshot`/`-test-run` `@smol:low`) is the "declared, not measured" list — all in the shipped package, so identical in every install and readable beside the scripts (`tier-roles.mjs:432` does exactly that with `join(SCRIPT_DIR, "..", "agents")`). `parseFrontmatter` (`tier-roles.mjs:97-102`) is the exported reader.

**Tier route.** `modelRoles.<role>` in the operator's omp config, never in the repo (CONTEXT.md:581-585). Resolved by `resolveRole(role, modelRoles)` (`tier-roles.mjs:116-122`: follows an `@other-role` chain up to 8 hops, strips `:<level>`, `null` when unset/cyclic). Read with `readOmpConfigValue("modelRoles")` = `omp config get modelRoles --json`, "the MERGED effective value (built-in defaults, global config, project settings, `--config` overlays, runtime overrides)" (`tier-roles.mjs:167-174`; `tier-roles.mjs:435` reads it the same way). `[local]` The maintainer's value: `slow: anthropic/claude-opus-5-5:high`, `task: anthropic/claude-sonnet-5-5:high`, `smol: anthropic/claude-haiku-5-5:auto` — the baked `:auto` is overridden by the Cell's declared `:high` (`tier-roles.mjs:2-7`). Spawning `omp` costs ~2.4 s `[local]`, so a per-tick call would be a poor fit for a 15 s tick; the Tier route wants its own slower cadence or a cached read.

**What omp does, per its docs.** `@<role>` resolves through `modelRoles` and the level on the referring alias wins (`omp://models.md:699`, `:710`; `omp://task-agent-discovery.md:76`). Unset `slow`/`smol` inherit `default`, then a built-in priority list (`omp://models.md:706-707`) — so an unset `modelRoles.slow` still runs *some* model, which `resolveRole` reports as `null`. `modelRoles` merges across global config, the project's `<cwd>/.omp/config.yml`, CLI overlays and runtime overrides (`omp://settings.md:19-22`; project `modelRoles` entries are the stated exception to null-as-unset, `omp://settings.md:168`), and `--profile`/`OMP_PROFILE` select a different settings directory altogether (`omp://settings.md:24`). The cockpit therefore resolves a Tier route that depends on *its own* cwd, profile and `--config`, which can differ from the controller's. omp's task preflight reloads settings before each task dispatch (`omp://task-agent-discovery.md:76`), but the repo's own note records that on omp 18.4.4 a `modelRoles` edit did not reach an agent registered at session start (`docs/components/tier-routing.md:41`).

**Consequence.** A Tier route is a statement about *now* and about the cockpit's own environment; the per-Pull model is the Resolved tier (below). The tab can flag "route differs from judged generation" by comparing `resolveRole(role)` with the guard's `cells[].generation` (both consumer records, with `modelsEqual`, `tier-roles.mjs:161-165`, since `modelRoles` values carry a provider prefix and `dispatch_model` does not) — and with the table's `estimates[*][cell].generation` for the routing evidence.

## 7. Resolved tier — member transcripts

`member-record.mjs` folds a transcript: `thinking` from the last `thinking_level_change.thinkingLevel` (`:401`), `resolvedModelIdentity` from `session_init` (`resolvedModelIdentity`, else `resolvedModel`, `:403-408`), `agent` (the dispatched definition = `subagent_type`, `:407`, `:840`), per-turn `model` from the last assistant turn that has `usage` (`:420`). `ompMemberRecord` returns all of them (`:826-846`; `thinking` is `"-"` when absent, `:837`). CONTEXT.md:574-579 defines the Resolved tier as that model identity plus the level event.

**What the cockpit keeps.** `readOmpSpend` builds `{label, role, model, cacheWrite, output, cacheRead}` from the record (`board-gather.mjs:639-642`): the per-turn `model` only. `thinking`, `resolvedModelIdentity` and `subagent_type` are on the record and dropped. ## 8. What a consumer's `ticket-router.mjs route` reads today

Inputs of `route` (`ticket-router.mjs:6-20`, `:641-688`): `--issue` (the scratch `issue.json`), `--guard`, `--sizing` (arm B only), `--table` (default: the installed one), the phase-0 receipt for session and Objective. The Pull passes `--session --ticket --arm --impl-row [--chain-head] --issue --guard` and no `--table` (`pull.mjs:942-945`), so:

- **Rows, `burn_in`, `cells`, `stage`, `classifier` → this repository's table** (`DEFAULT_TABLE`, `:62`, `:641`).
- **`tripped` → the consumer's own guard** (`readGuard`, `:175-185`); its per-Cell `n` and `window_start` are not read by `route` (they feed the fit's snapshot).
- **No guard → default Cell only** (`:248-252`).
- **Tripped Cell** replaces policy/base with `slow-high` (`table-cell-tripped`, `:254-260`); on an exploring Pull a tripped Cell leaves the draw (`guard-tripped`, `:262-266`; K shrinks).

So the consumer's evidence can only *remove* Cells from routing; **which Cell a row routes to, and the burn-in uniform draw, are this repository's evidence**. The consumer's guard explains why a Cell is *held back* in the consumer; the table explains why a Cell is *chosen*, and for a consumer that "why" is about the maintainer's models and corpus.

A consumer cannot refit: `fit` and `--check` take `fitted_commit` as a commit of *the repository holding `--features`* and die when it is not there — "was fitted from commit …, which this repository does not hold — run `git fetch`" (`ticket-router.mjs:706-714`). The script ships, but the chore-PR duty and the tracked `router-table.json` in the consumer's checkout do not exist; a `fit --table` could be pointed at a consumer's TSVs by hand, and would then fit the consumer's corpus (`[INFERENCE]`; I ran `fit` only in this repository).

**Can `estimates`/`reasons` describe models the consumer's `modelRoles` does not run?** Yes, structurally:
- `estimates[stratum][cell].generation` and `older` key figures by the *model* the maintainer's Cell ran on (`ticket-router.mjs:344-349`; `[local]` preview: `claude-sonnet-5-5` for `task-high`).
- `reasons` and `rows` mention only Cell tokens; a verdict "task-high qualifies over slow-high" is true of the maintainer's `task` and `slow` model roles, and a consumer whose `modelRoles.task` names another model inherits the verdict with no model attached.
- Nothing in `route`, `validateTable` or the guard compares a table generation with the consumer's Tier route or its own Cell generations.
- The comparison is possible from records alone: table `estimates.*.generation` vs the consumer guard's `cells[].generation` (both model names) vs `resolveRole` (the Tier route).
- The consumer's own guard judges *its own* newest generation per Cell (`pr-cost.mjs:55-58`): when a consumer swaps a model role, the guard reacts at 20 merged PRs and the table never does.

**Consequence for burn-in.** The shipped table says `burn_in: true`; ends only by a re-fit that the consumer never receives except through a plugin release. Until then, every consumer Pull is an Exploration Pull: `draw = drawCell({ session, ticket, policyCell: null, cells: table.cells minus tripped })` (`ticket-router.mjs:262-271`; `pull.md:432-437`), with `policy_cell` = the table's `cost` row (`slow-high`) and `chosen_cell` uniform over three.

## Findings that matter most to the next tickets

1. **Two evidence sources, two owners.** In a consumer, "what routes" is the maintainer's table; "what the guard holds a Cell to" is the consumer's corpus. The tab has to label which is which (`fitted_commit` and `n_rows` for one; `computed_at` and `n` for the other), and a consumer's `fitted_commit` is a commit it does not hold: `--due` and `--check` die on it (`ticket-router.mjs:706-714`), so "merged PRs since the fit" is not computable in a consumer once the table is fitted.
2. **The consumer's first states are distinct and visible:** no guard (`guard-missing`), then a guard with `verdict: "none"` under burn-in, then trips; and the scrape/ruling writers assume `docs/metrics/` exists (verified for the scrape).
3. **The guard file is thinner than the figures the map wants** (no claims/failed counts, no `left_out`/`unpriced`, no older generations). Exact floor gap and per-Cell trust counts need a recompute (`computeReport`, ~4–5 s with its `gh` call) or the table's `estimates`.
4. **Per-Pull "why" lives in four places of different durability:** the pending TSV and ticket-features (Cell + draw, no reason, no Stratum), the ledger tokens (`tier=` drawn only, `route=` non-`ok` only; one run), and the scratch `pull.json` (the full routing line; not versioned, one per ticket). A card can only show `REASON=ok` and `STRATUM` from `pull.json` or a recompute.
5. **The gather drops what a card needs:** `thinking`, dispatch-time `resolvedModelIdentity` and `subagent_type` are on the record built at `board-gather.mjs:639-642` and discarded; the per-turn `model` it keeps is not what the Cell generation keys on.
6. **Cadences are all slower than the 15 s tick** and mutually inconsistent in time: table (release), guard (phase 0, close-out), member TSV (close-out), tier-outcomes (mid-run), pending (each Pull), `modelRoles` (any time, ~2.4 s to read). Reading by `stat` and re-parsing on change is cheap; the 6.8 MiB parse is ~0.7 s.
