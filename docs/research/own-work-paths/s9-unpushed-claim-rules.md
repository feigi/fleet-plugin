### S9-1 CONTEXT.md defines Upstream as absent at claim time, Reap/Release by that

### S9-2 claim-ticket.sh cuts the claim `--no-track`, so a fresh claim has no Upstream and is deliberately not `[gone]`
- Where: `plugin/scripts/claim-ticket.sh:280,317-318` (the command), `claim-ticket.sh:288-316` (comment block), `claim-ticket.sh:314-316` ("`--no-track` is also why no branch delete uses `-d`")
- Rule: "`--no-track`: without it … `@{u}` RESOLVES — to main." "No upstream at all, rather than one pre-seeded at refs/heads/$branch: … an upstream naming a remote ref that has never existed reads as `[gone]` … measured, a freshly claimed branch was reaped by `reap.sh --apply` before any work was done in it. The real upstream arrives with the first push with `-u` … or else when the controller settles the implementer's report … Only then can the branch be `[gone]`. Until then reap.sh weighs it as a branch with no upstream, and a fresh claim stays kept." "Where there is no GitHub repository to ask, it is never selected at all."
- Infers from "unpushed / no upstream / tip at origin/main": no upstream ⇒ not `[gone]` ⇒ reap cannot select it on the `[gone]` arm; "did my push land?" checks (`@{u}`, `git status -sb`) fail loudly rather than answer about main; `git branch -d` against an upstream-less branch measures against local HEAD.
- If the claim branch existed on origin from claim time (pushed at claim, possibly one claim-only commit): the "freshly claimed branch stays kept" argument rests on the branch having no upstream; with a pushed ref the upstream-less arm (S9-8) would see `origin/<b>` present and keep it for that reason instead, and the `[gone]` arm would not select it until the remote ref is deleted. A `--no-track` claim pushed without `-u` would still read "no upstream". The `@{u}` "my push landed?" hazard text assumes the member's `@{u}` would otherwise point at main; a claim-time `push -u` would make `@{u}` resolve to the branch's own remote ref.
- Pinned by: `tests/claim-lifecycle.test.mjs:95` ("a freshly claimed branch is not [gone], and reap.sh leaves it alone"; `:105-107` asserts `@{u}` fails with `no upstream configured`), `:122` ("after push -u, merge and prune, reap.sh does see the branch as [gone]"), `:148` (release of an untouched claim while local main is stale); `tests/claim-ticket.test.mjs:140-146` states the `--no-track` assertion lives in claim-lifecycle, not there; `tests/push-sync.test.mjs:70,312` build the fixture with `--no-track`.

### S9-4 release-ticket.sh: the "never dispatched" shape is defined as no branch on origin and no commit beyond origin/main
- Where: `plugin/scripts/release-ticket.sh:4-7` (header), `release-ticket.sh:885-907` (live `ls-remote --heads origin refs/heads/$branch`), `release-ticket.sh:948-981` (no branch + no remote ⇒ usage die), `release-ticket.sh:996-1018` (no remote ⇒ `ahead` = `rev-list --count base_rev..refs/heads/$branch` must be 0 and `git cherry` must print no `+`)
- Rule: "Never dispatched: no branch on origin. The branch must carry no commit beyond origin/main and no commit unique to it." Else `block "$ahead commit(s) ahead of $base"` / `block "$uniq commit(s) unique to $branch (git cherry)"`.
- Infers from "unpushed / no upstream / tip at origin/main": a claim with no remote ref and tip == `origin/main` carries no work, so deleting local branch + worktree + label loses nothing; a claim that is ahead of `origin/main` carries unpushed work and is refused.
- If the claim branch existed on origin from claim time: the claim leaves the "never dispatched" shape at once and enters the "pushed branch" shape (S9-5), so a pristine claim can no longer release through this arm; with one claim-only commit on top of `origin/main` the `ahead`/`cherry` arm would read it as work (`1 commit(s) ahead of origin/main`) even where nothing of the member's exists.
- Pinned by: `tests/release-ticket.test.mjs:392` ("a clean undispatched claim releases all three artefacts"), `:499` ("a commit already upstream-equivalent still blocks: `ahead` catches what…"), `:526` ("a commit that exists nowhere else blocks"), `tests/claim-lifecycle.test.mjs:148,177`; `tests/release-ticket-reap-pairing-prose.test.mjs` pins the comment pairing with reap.

- Rule: "Remote check catches a pushed branch … A pushed branch blocks unless it is the closed-unmerged shape." "A branch on origin with no PR … blocks."
- Infers from "unpushed / no upstream / tip at origin/main": a remote ref means a member pushed work (the work "already on the server"); absence of a PR on a pushed branch means a half-finished hand-off, which must not be auto-released.

### S9-6 release-ticket.sh: delete-time recount and the `-d` retirement assume a pristine claim's tip equals origin/main

### S9-10 reap.sh `[gone]` selection plus `git cherry` authorises a delete only after an upstream exists; the comment in claim-ticket.sh names the one-shot failure
- Where: `plugin/scripts/reap.sh:1063` (`$3=="[gone]"`), `reap.sh:1204-1244` (`git cherry "$base_rev" "$tip"`: no `+` ⇒ merged; `+` ⇒ kept unless `pr_tie`), `reap.sh:9-14`; `claim-ticket.sh:300-312`; `release-ticket.sh:19-24` ("no remote branch was ever deleted, so the branch is not [gone] and reap's for-each-ref filter never selects it. - Rule: reap's evidence is "merged upstream": a local branch is reapable only if the remote ref it tracks is gone (`[gone]`) and every commit is patch-equivalent on `origin/main` (or tied to the merged PR's heads). A branch with an empty cherry and a `[gone]` upstream is authorised.
