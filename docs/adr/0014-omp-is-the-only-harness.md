# 0014 — omp.sh is the only harness

**Status:** Accepted. Ruled 2026-09-27.

## Context

The fleet plugin has been dual-harness since ADR 0004 (2026-09-09): one tree,
harness-neutral prose with adjacent `CLAUDE:`/`OMP:` marked lines at every
dispatch site, dual tier keys (`effort:` + `thinking-level:`) in every agent's
frontmatter routed through an operator-side `task.agentModelOverrides` record
(ADR 0011), a resolver that picks a harness (ADR 0003), a Claude Code workflow
host (`plugin/workflows/review-pr.js`) beside the omp `eval` review host, and
CI jobs validating both.

The maintainer ruled Claude Code support is dropped entirely, whole-surface,
single-operator, no compatibility shims (2026-09-27). The dual-harness design
was never a hedge against Claude Code disappearing — it was carrying two live
consumers because both were genuinely in use. That is no longer true: this
port now runs on omp.sh alone, and every dual-harness workaround that existed
solely to keep Claude Code's dialect readable, its tier syntax parseable, and
its workflow host runnable is now dead weight with no second consumer to
justify it.

## Decision

1. **omp.sh is the only harness.** Claude Code support is removed
   whole-surface: every `CLAUDE:` marked line, every Claude-only code path,
   every dual-harness test fixture, and the CI job that validated a Claude
   Code install. A fleet artefact that names Claude Code's tools is a defect,
   not a variant (CONTEXT.md § Harness).
2. **Tier is one frontmatter key.** `model: "@<role>:<level>"`
   (`@slow`/`@task`/`@smol`, an explicit level suffix) replaces the
   `effort:`/`thinking-level:` pair ADR 0005 declared and the
   `task.agentModelOverrides` derivation ADR 0011 built on top of it.
   `task.agentModelOverrides` is retired as an install-time precondition —
   omp resolves a role alias in frontmatter `model:` through `modelRoles`
   natively, and an explicit `:level` suffix on the referring alias wins
   over the role's own baked suffix. `tier-roles.mjs --check` now guards two
   things instead of deriving a record: every definition's `model:` is a
   well-formed route, every role a definition names resolves under
   `modelRoles`, and — the shadowing case ADR 0011's layer no longer needs
   but a stale operator config could still create — no
   `task.agentModelOverrides` entry survives naming a fleet definition.
3. **Marked lines and the pair discipline are retired.** A dialect pair with
   one dialect is dead weight. Prose names omp's own tools directly —
   `hub send` instead of a Send that split by harness, `eval` instead of a
   Workflow-vs-`eval` split reviewer path. `marked-pairs.mjs` and every pair
   pin are deleted with them (CONTEXT.md's whole § Dialect section is gone).
4. **`plugin/workflows/` is retired.** `review-core.mjs` (the pure
   functions and `runReview`) plus `review-eval.mjs` (the omp entry point)
   plus the `fleet-review-runner` agent definition is the sole review host.
   Nothing in this port names `review-pr.js` or a Claude Task-tool `Workflow`
   again.
5. **The Resolver reads one registry.** `~/.fleet/bin/fleet-run` resolves
   `~/.omp/plugins/installed_plugins.json` and nothing else — no harness
   detection, no `FLEET_HARNESS` override, no byte-identical-`scripts/`
   shortcut standing in for a second install it no longer needs to
   disambiguate from.
6. **The root catalog moves; the plugin manifest does not.**
   `.claude-plugin/marketplace.json` becomes `.omp-plugin/marketplace.json`
   — omp's preferred path when omp is the only intended consumer. `plugin/
   .claude-plugin/plugin.json` stays byte-for-byte at its existing path:
   omp loads commands/skills/agents from that path only, measured (ADR 0004
   § Context), so moving it would break the one thing that still has to
   read it.
7. **`enabledProviders: ["claude-plugins"]` stays.** It is omp's own
   provider name for the plugin loader, a hard install-time precondition
   (ADR 0003 point 8), unrelated to Claude Code's presence or absence on the
   machine.

## Rejected alternatives

- **Keeping marked lines, with the `OMP:` half promoted and the `CLAUDE:`
  half left as a comment.** A pin with nothing left to discriminate against
  is dead weight wearing the shape of a live guard — the next reader has no
  way to tell a genuinely retired rule from one still doing work.
- **Keeping `task.agentModelOverrides` as a generated cache of the
  definitions' own `model:` values.** A second copy of the same fact,
  regenerated by hand after every definition change and never itself the
  source of truth, is exactly the drift hazard ADR 0011 already measured for
  the two-key tier declaration it replaced — moving the redundancy one layer
  down does not remove it.

## Consequences

- ADR 0003, 0004, 0005, 0006, 0008, and 0011 are amended or superseded by
  this ADR; each carries its own amendment note (see each file's own
  `**Status:**` line).
- CI's `install-and-smoke` job now proves the install-only dev loop against
  one harness, not two — the measured 70/1964-failure reproduction that
  drove its original design (installed-copy-cannot-run-the-suite) still
  applies, just without the second harness's install/uninstall pass.
- `docs/metrics/member-outcomes.tsv`'s `harness` column is constant `omp`
  from this ADR's date forward; historic rows still carry `claude`. Re-
  columning the corpus and every awk recipe in
  `docs/specs/2026-08-27-fleet-member-outcomes-plan-1-scraper.md` that reads
  it is churn with no gain and is not done here.
- `docs/specs/`, `docs/research/`, and `.out-of-scope/` are historical
  record of the dual-harness era and are untouched, including the marked
  lines inside `docs/specs/2026-09-24-slot-based-fleet-loop-design.md`
  (never dispatched — `marked-pairs.mjs`'s scope excluded `docs/` by
  design, and this ADR does not reopen that scope).
